Your buckets. Your keys. No one in between.

sThree Browser is a safe, open-source S3 browser. Your credentials stay encrypted on your device, and every request goes straight from you to your storage.

Open the app Host your own

Works with AWS S3, Cloudflare R2, MinIO and any S3-compatible storage.

The shortest path
is the safest one.

Most tools pass your keys through someone's server. sThree doesn't have one. The host only hands your browser some static files; after that it's just you and your bucket.

An encrypted vault

Connections and credentials are one AES-256-GCM ciphertext, keyed from your master password with scrypt. On desktop it's also bound to the OS keychain.

Signed on your device

Every S3 request is signed locally and sent straight to the storage endpoint. The site's host never sees a key, a file or a request.

Zero tracking

No analytics, no telemetry. This page doesn't load a single file from anywhere else either.

Host it yourself
in one line.

The web version is a folder of static files in a 13 MB image. No application server, a non-root user, and nothing that ever touches your data.

  • Strict Content-Security-Policy and no-referrer headers
  • GET /health for your orchestrator
  • Or any static host: nginx, Caddy, Cloudflare Pages, Netlify
Terminal
$ docker run -d -p 8888:8888 --name sthree-browser ghcr.io/mohamadtahir/sthree-browser:latest

Open http://localhost:8888, then serve it over HTTPS.

Bucket CORS rule for the web version

Your browser talks to S3 directly, so each bucket must allow your site's origin. The app shows this exact rule when one is missing.

[{
  "AllowedOrigins": ["https://sthree.example.com"],
  "AllowedMethods": ["GET", "PUT", "POST", "DELETE", "HEAD"],
  "AllowedHeaders": ["*"],
  "ExposeHeaders": ["ETag", "Content-Length", "Content-Type", "Last-Modified"],
  "MaxAgeSeconds": 3600
}]
